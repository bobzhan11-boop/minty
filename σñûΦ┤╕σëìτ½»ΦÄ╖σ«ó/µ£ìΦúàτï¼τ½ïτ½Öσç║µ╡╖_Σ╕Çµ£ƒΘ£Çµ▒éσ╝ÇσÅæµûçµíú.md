## 一、项目概述

### 1.1 项目定位

面向全球 B2B 市场的服装 POD（Print-On-Demand）定制独立站。以**询盘驱动**为核心交易模式，网站承担品牌展示、工厂实力呈现、客资获取三大职能，最终通过人工跟进完成成交闭环。

### 1.2 一期核心目标

一期聚焦于"跑通询盘链路"，具体目标包括：网站上线并稳定运行；询盘表单 + WhatsApp 双通道可正常接收客资；后台可管理商品、工厂、案例等展示内容；基础数据埋点上线，可追踪核心转化指标。

### 1.3 技术选型总览

| 层级 | 选型 | 说明 |
|------|------|------|
| 前端框架 | Next.js 14 (App Router) | SSR/SSG 混合渲染，利于 SEO |
| UI 组件 | Tailwind CSS + shadcn/ui | 快速构建一致的视觉体系 |
| 后端服务 | Next.js API Routes + Prisma ORM | 与前端同仓库部署，降低联调成本 |
| 数据库 | PostgreSQL | 结构化存储客户、商品、案例等核心数据 |
| 对象存储 | 阿里云 OSS / AWS S3 | 存放图片及产品短视频 |
| 视频托管 | YouTube（工厂长视频）+ 对象存储（产品短视频） | 混合方案，兼顾加载速度与成本控制 |
| 部署 | 云服务器（阿里云 / AWS） | Docker + Nginx 统一部署 |
| 缓存 | Redis | 会话管理、热门数据缓存、限流 |
| 邮件通知 | Resend / SendGrid | 询盘提交后的邮件提醒 |
| 埋点分析 | Google Analytics 4 + 自建事件日志 | GA4 做宏观分析，自建日志做精细化追踪 |

## 二、客户端（前台）功能需求

### 2.1 页面结构总览

```
/                        → 首页（Homepage）
/products                → 商品展示（Products）
/products/[id]           → 商品详情（Product Detail）
/custom-order            → 定制下单 / POD 介绍（Custom Order）
/about                   → 品牌故事 & 工厂介绍（About / Factory）
/showcase                → 案例展示（Showcase）
/showcase/[id]           → 案例详情（Case Detail）
/contact                 → 联系我们 / 询盘表单（Contact）
/account                 → 个人中心（登录后可访问）
/account/inquiries       → 我的询盘记录
/account/designs         → 我的设计稿
/account/favorites       → 我的收藏夹
/privacy                 → 隐私政策（Privacy Policy）
/terms                   → 服务条款（Terms of Service）
```

### 2.2 首页（Homepage）

**定位**: 30 秒内让 B 端客户理解"你是谁、你能做什么、为什么要联系你"。

**模块组成**:

- **Hero 区域**: 采用"极简数字前台"交互，**白底 + 站内品牌色（minty 绿）** 配色。**全屏背景**为项目介绍文案的**流动文字**（多行大号黑色字体、低透明度、左右交替横向滚动 marquee，铺满全屏，位于数字人背后）。**默认状态**：数字店员（欧美真人 MP4 循环，底部渐隐为投影质感，未就绪时回退静态封面图 poster）**居中**展示 + 柔和品牌绿光晕/投影光锥，下方仅 "Online" + 店员名 + "Hover or tap to chat" 提示，右侧无介绍文案，保持干净。**激活后**（鼠标悬停 / 点击 / 键盘聚焦数字人）：数字人左移，右侧滑出白色对话控制台（站内配色），含品牌介绍（Slogan H1 + 副标题）、核心 CTA 按钮（"Get a Quote" / "View Products"）、与数字店员的对话功能（对话气泡 + 快捷问题 + 输入框，一期为前端模拟对话、关键词引导）及 WhatsApp 引流；控制台可关闭回到默认居中状态。
- **核心优势区**: 3-4 个图标卡片，展示差异化优势（如：自有工厂、MOQ 灵活、全球发货、POD 定制能力）。
- **精选商品轮播**: 展示 6-8 款核心产品缩略图，点击跳转商品详情。
- **工厂实力速览**: 1-2 张工厂实景大图 + "深入了解"按钮，链接到 About 页面。
- **客户案例/Logo 墙**: 合作品牌 Logo 或客户评价（如有）。
- **底部 CTA**: 询盘表单入口或 WhatsApp 浮动按钮。

**SEO 要求**: H1 标签包含核心关键词（如 "Custom Apparel Manufacturer"）；Hero 区域图片带 alt 属性；首屏 LCP（Largest Contentful Paint）控制在 2.5 秒内。

### 2.3 商品展示（Products）

**列表页**:
- 支持按品类（T恤、卫衣、帽子等）筛选
- 每个商品卡片包含：主图、商品名称、MOQ 信息、"Inquire Now"按钮
- 分页加载或无限滚动（建议分页，利于 SEO 爬取）

**详情页**:
- 商品主图 + 多角度图片画廊（支持放大查看）
- 产品短视频（如有，从对象存储加载）
- 商品描述：材质、工艺、可定制范围
- MOQ 及价格梯度说明（展示策略：显示"From $X.XX"或"Contact for pricing"）
- 规格参数表（可下载 PDF）
- 相关商品推荐
- "Send Inquiry" 表单（预填商品信息）+ WhatsApp 按钮

### 2.4 POD 定制介绍（Custom Order）

**定位**: 解释 POD 定制流程，降低客户咨询门槛。

**内容**:
- 定制流程可视化（4-5 步流程图：选品 → 提交设计 → 确认样品 → 批量生产 → 发货）
- 可定制品类展示（图片网格）
- 底部询盘表单（预填"POD 定制"标签）

### 2.5 品牌故事 & 工厂介绍（About / Factory）

**品牌故事**:
- 品牌创立背景、使命愿景
- 图文混排，支持嵌入品牌宣传视频（YouTube 嵌入）要求站内播放

**工厂展示**:
- 工厂全景视频（YouTube 嵌入，建议 2-3 分钟）要求站内播放
- 工厂实景图片画廊（生产线、仓库、质检环节）
- 文字呈现资质认证展示（ISO、OEKO-TEX 等证书图片）

### 2.6 案例展示（Showcase）

**列表页**:
- 案例卡片：封面图 + 客户行业/地区 
- 可按行业/品类筛选

**详情页**:
- 定制过程图文记录
- 成品展示图片/视频
- 客户评价（如有）
- "Start Your Project" CTA

### 2.7 联系我们 / 询盘表单（Contact）

**询盘表单字段**:
- 姓名（必填）
- 邮箱（必填，带格式校验）
- 公司名称（选填）
- 国家/地区（下拉选择）
- 联系电话（选填，含国际区号）
- 感兴趣的产品/服务（多选标签）
- 预计数量（选填）
- 详细需求描述（多行文本）
- 附件上传（设计稿或参考图，最大 20MB）
- 提交按钮

**表单行为**:
- 前端实时校验，错误提示内联显示
- 提交后显示成功提示页，包含预计响应时间（如 "We'll get back to you within 6 hours"）
- 提交数据写入数据库，并触发邮件通知（通知运营人员）
- 每次提交记录来源渠道（UTM 参数 / 页面来源）

**WhatsApp 集成**:
- 全站右下角悬浮 WhatsApp 按钮
- 点击后跳转 WhatsApp Web/App
- WhatsApp 链接包含 `?text=` 参数，方便追踪来源页面
- **追踪说明**: WhatsApp 跳转仅产生 `whatsapp_click` 埋点事件（写入 `tracking_events` 表），不创建询盘记录（因为用户离开站点后无法回收表单数据）。运营仪表盘中"WhatsApp 点击次数"从埋点日志统计，而非询盘表

### 2.8 用户注册（轻量入口）

**定位**: 非强制注册，注册目的是方便客户后续查看自己的询盘记录和设计稿。

**注册字段**:
- 邮箱
- 密码
- 公司名称（选填）

**个人中心**:
- 基本信息编辑（姓名、公司、联系方式）
- 我的询盘记录（状态：待回复 / 已回复 / 进行中 / 已完成）
- 收藏夹（收藏/取消收藏商品和案例）

**说明**: 个人中心为非强制功能，客户可不注册直接通过表单或 WhatsApp 提交询盘。注册客户额外享有询盘记录查看和设计稿管理功能。

### 2.9 公共组件 & 全站功能

- **导航栏**: Logo + 菜单项 + 语言切换（一期仅英文，预留接口）+ "Start chat" CTA 按钮
- **页脚**: 公司信息、快速链接、社交媒体图标、隐私政策/服务条款链接
- **WhatsApp 悬浮按钮**: 全站可见，移动端固定在右下角
- **面包屑导航**: 内页统一展示
- **SEO Meta**: 每个页面独立的 title、description、OG 标签
- **Sitemap**: 自动生成 `/sitemap.xml`
- **robots.txt**: 配置爬虫规则
- **404 页面**: 品牌化设计，引导返回首页

## 三、后台管理系统功能需求

### 3.1 后台入口 & 权限

- 独立路由 `/admin`，需登录访问
- 角色设计（一期实现两种）：
  - **管理员**: 全部权限
  - **运营人员**: 内容编辑权限（不可修改系统设置和用户管理）
- 登录方式：邮箱 + 密码（一期），预留 OAuth 扩展接口

### 3.2 内容管理模块

所有模块均支持**多模态内容编辑**（文字 + 图片 + 视频），运营人员通过后台表单更新，前端实时同步展示。

#### 3.2.1 商品管理

- 商品 CRUD（创建/读取/更新/删除）
- 字段：名称、品类、描述（富文本）、主图（多图上传）、视频（上传至对象存储或粘贴 YouTube 链接）、MOQ、价格梯度、规格参数、标签
- 排序管理（拖拽排序或手动设置权重）
- 上架/下架状态切换
- 批量导入（CSV 格式，二期实现）

#### 3.2.2 工厂展示管理

- 编辑工厂介绍文案（富文本编辑器）
- 管理工厂图片画廊（上传/排序/删除）
- 管理工厂视频（YouTube 链接或上传视频文件）
- 编辑产能数据（数字字段，前端以动画数字展示）
- 管理资质认证（证书名称 + 图片上传）

#### 3.2.3 案例展示管理

- 案例 CRUD
- 字段：标题、客户行业、地区、项目描述（富文本）、封面图、过程图片、成品图片/视频、客户评价文本
- 排序管理
- 上架/下架

#### 3.2.4 品牌故事管理

- 编辑品牌故事文案（富文本）
- 管理品牌宣传视频（YouTube 链接）
- 管理品牌图片

#### 3.2.5 首页模块管理

- Hero 区域：编辑背景图/视频、Slogan 文案、CTA 按钮文字和链接
- 核心优势区：编辑每个优势卡片的图标、标题、描述
- 精选商品：从商品库中选择推荐商品
- 客户 Logo 墙：上传/管理合作品牌 Logo

### 3.3 客户管理（轻量 CRM）

**核心定位**: 服务于人工客户维护，非自动化营销。

#### 3.3.1 客户数据库

- 数据来源：询盘表单提交 + 手动录入
- 客户字段：姓名、邮箱、公司、国家、电话、来源渠道、创建时间
- **标签系统**: 支持为每个客户打多个标签（如"VIP"、"待跟进"、"已报价"、"已成交"、"POD客户"等），标签可自定义创建
- 客户状态流转：新线索 → 已联系 → 已报价 → 谈判中 → 已成交 / 已流失
- 客户详情页：查看基本信息 + 全部询盘记录 + 跟进备注 + 标签

#### 3.3.2 询盘管理

- 询盘列表：按时间倒序，支持按状态、来源、关键词筛选
- 询盘详情：查看完整表单内容
- 状态管理：待回复 → 已回复 → 进行中 → 已完成 / 已关闭
- 备注功能：运营人员可添加内部跟进备注
- 关联客户：询盘自动关联到对应客户手动关联

#### 3.3.3 客户数据导出

- 支持按标签/状态/时间范围筛选导出
- 导出格式：CSV / Excel

### 3.4 数据埋点 & 运营仪表盘

#### 3.4.1 前端埋点方案（一期基础版）

采用"GA4 + 自建事件日志"双轨方案。GA4 负责宏观流量分析，自建日志负责精细化业务追踪。

**必须埋点的核心事件**:

| 事件名称 | 触发条件 | 关键参数 | 追踪目的 |
|---------|---------|---------|---------|
| `page_view` | 页面加载 | page_path, referrer, utm_source | 流量来源分析 |
| `inquiry_form_view` | 询盘表单可见 | page_path | 表单曝光率 |
| `inquiry_form_submit` | 表单提交成功 | page_path, source_page, has_attachment | 核心转化 |
| `whatsapp_click` | 点击 WhatsApp 按钮 | page_path, button_location (float/detail_cta/hero_concierge) | WhatsApp 转化追踪 |
| `product_view` | 查看商品详情 | product_id, product_name, category | 热门商品分析 |
| `product_inquiry` | 从商品页发起询盘 | product_id, product_name | 商品转化归因 |
| `video_play` | 播放视频 | video_id, video_type (factory/product), page_path | 内容互动分析 |
| `file_download` | 下载规格书/文件 | file_name, product_id | 高意向行为识别 |
| `cta_click` | 点击各类 CTA 按钮 | button_text, page_path, position | CTA 效果对比 |

**埋点实施原则**:
- 使用统一的事件上报函数 `trackEvent(name, params)`，前端统一封装
- 所有事件同时上报至 GA4（通过 `gtag.js`）和自建日志 API（`POST /api/events`）
- 自建日志写入数据库 `tracking_events` 表
- 避免过度埋点：一期不做鼠标热力图、不做页面滚动深度追踪、不做 A/B 测试框架

#### 3.4.2 运营仪表盘（后台首页）

**核心指标卡片**（顶部 4-6 个数字卡片）:
- 今日/本周/本月 页面访问量（PV）
- 今日/本周/本月 独立访客数（UV）
- 新询盘数量（今日/本周/本月）
- WhatsApp 点击次数（今日/本周/本月）
- 询盘转化率（询盘数 / 访客数）
- 待回复询盘数（红色高亮提醒）

**图表模块**:
- 流量趋势图（近 7 天 / 30 天折线图）
- 询盘来源分布（饼图：UTM 来源 / 页面来源）
- 热门商品 Top 10（按浏览量 / 询盘量排序）
- 询盘状态漏斗（新线索 → 已回复 → 已报价 → 已成交）
- WhatsApp vs 表单 询盘占比

**数据来源**:
- PV/UV 数据从 GA4 API 拉取（或从自建日志统计）
- 询盘/WhatsApp 数据从业务数据库统计
- 仪表盘数据每小时刷新一次（缓存策略），非实时

### 3.5 营销接口（预留）

一期不实现具体功能，但预留以下 API 接口结构，方便二期接入：

- `POST /api/newsletter/subscribe` — 邮件订阅（接入 Mailchimp 等）
- `POST /api/coupon/apply` — 优惠码校验
- `GET /api/promotions` — 促销活动列表
- `POST /api/webhooks/[platform]` — 第三方平台 webhook 接收（如 Facebook Lead Ads）

接口一期返回 `501 Not Implemented`，前端不展示相关 UI。

### 3.6 风控系统（基础安全）

**一期实现范围**:

- **表单防刷**: 提交频率限制（同一 IP 每小时最多 5 次询盘提交）；集成 Google reCAPTCHA v3（无感验证）
- **API 限流**: 基于 Redis 的滑动窗口限流，防止接口被恶意调用
- **XSS / CSRF 防护**: Next.js 内置 + 自定义中间件
- **SQL 注入防护**: Prisma ORM 参数化查询（框架自带）
- **HTTPS 强制**: Nginx 层配置 HTTP → HTTPS 重定向
- **文件上传安全**: 限制文件类型（仅允许图片、PDF、AI）和大小（最大 20MB），上传后杀毒扫描
- **后台访问控制**: JWT Token + 角色权限校验
- **日志审计**: 记录后台所有敏感操作（删除商品、修改权限等）

**一期不做**:
- 不做 DDoS 防护（依赖云服务商基础防护）
- 不做行为风控（异常访问模式识别等）
- 不做 GDPR Cookie 弹窗（目标市场如需欧洲再补）

## 四、数据库设计要点

### 4.1 核心表结构

**用户与客户相关**:
- `users` — 网站注册用户 + 后台管理员
- `customers` — 客户主表（可与 users 通过 email 关联，也支持手动录入）
- `customer_tags` — 标签定义表
- `customer_tag_relations` — 客户-标签多对多关联
- `customer_notes` — 客户跟进备注

**内容相关**:
- `products` — 商品主表
- `product_images` — 商品图片（一对多）
- `product_videos` — 商品视频（一对多，支持 YouTube 链接或对象存储 URL）
- `product_categories` — 商品品类
- `cases` — 案例主表
- `case_images` — 案例图片
- `factory_info` — 工厂信息（单行记录）
- `factory_images` — 工厂图片
- `factory_certifications` — 工厂资质认证（证书名称 + 图片 + 有效期）
- `brand_content` — 品牌故事内容
- `home_modules` — 首页各模块配置（含 Logo 墙数据，存储于 JSON 字段中）

**用户扩展相关**:
- `user_favorites` — 用户收藏（user_id + resource_type + resource_id，支持收藏商品和案例）
- `user_designs` — 用户上传的设计稿（user_id + 文件 URL + 文件名）

**业务相关**:
- `inquiries` — 询盘记录
- `inquiry_attachments` — 询盘附件
- `inquiry_notes` — 询盘内部跟进备注（运营人员使用）

**系统相关**:
- `tracking_events` — 埋点事件日志
- `admin_logs` — 后台操作审计日志

### 4.2 关键设计原则

- 所有业务表包含 `created_at` 和 `updated_at` 时间戳字段
- 内容表（products, cases 等）包含 `status` 字段（draft / published / archived）
- 图片/视频存储 URL 存数据库，实际文件存对象存储
- 客户标签采用多对多关系，方便灵活扩展
- 埋点事件表按月分区（partition），避免单表过大影响查询性能
- 敏感字段（如客户邮箱）加密存储

## 五、API 接口设计要点

### 5.1 接口规范

- RESTful 风格，统一前缀 `/api/v1/`
- 统一响应格式：`{ "code": 200, "message": "success", "data": {...} }`

## 六、非功能性需求

### 6.1 性能要求

- 首页 LCP（最大内容绘制）≤ 2.5 秒
- 首页 FID（首次输入延迟）≤ 100ms
- 首页 CLS（累积布局偏移）≤ 0.1
- API 接口响应时间 ≤ 500ms（P95）
- 图片统一使用 WebP 格式 + 懒加载
- 静态资源接入 CDN 加速

### 6.2 SEO 要求

- 全站 SSR/SSG 渲染，确保搜索引擎可爬取
- 每个页面独立 Meta Title / Description
- Open Graph 标签（og:title / og:image / og:description）
- 结构化数据标记（Organization / Product / FAQ Schema）
- 自动生成 Sitemap + robots.txt
- URL 语义化（如 `/products/custom-tshirt` 而非 `/products/123`）

### 6.3 兼容性要求

- 响应式设计，适配 PC / 平板 / 手机
- 浏览器兼容：Chrome / Safari / Firefox / Edge 最近两个主要版本
- 移动端优先设计（询盘表单和 WhatsApp 按钮在移动端需显著可见）

### 6.4 安全要求

- 全站 HTTPS
- 用户密码 bcrypt 加盐哈希存储
- JWT Token 设置合理过期时间（Access Token 2小时 + Refresh Token 7天）
- 后台接口 RBAC 权限校验
- 文件上传类型/大小校验 + 存储隔离

## 七、部署架构

```
                     ┌──────────────┐
                     │   Nginx      │
                     │  (反向代理)   │
                     │  SSL终止     │
                     │  静态资源CDN  │
                     └──────┬───────┘
                            │
              ┌─────────────┼─────────────┐
              │             │             │
     ┌────────▼───┐  ┌─────▼──────┐  ┌──▼────────┐
     │ Next.js    │  │ Next.js    │  │  Redis    │
     │ 前端 SSR   │  │ API Routes │  │  缓存/限流 │
     └────────────┘  └─────┬──────┘  └───────────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
     ┌────────▼───┐  ┌────▼─────┐  ┌──▼──────────┐
     │ PostgreSQL │  │ 对象存储  │  │  YouTube    │
     │  数据库     │  │ OSS/S3   │  │  (工厂视频) │
     └────────────┘  └──────────┘  └─────────────┘
```

**部署组件**:
- **Nginx**: 反向代理 + SSL 证书终止 + 静态文件服务
- **Next.js 应用**: Docker 容器部署，PM2 进程管理
- **PostgreSQL**: 云数据库服务（建议 RDS 或阿里云 PolarDB），每日自动备份
- **Redis**: 缓存 + 会话管理 + 限流计数
- **对象存储**: 图片/视频文件存储，配合 CDN 分发
- **日志**: 应用日志写入文件 + 云监控告警
